# Placement Predict — Follow-up Audit 2026-10-07

## Scope

Follow-up audit of the current `main` branch after the original forensic audit and CI #37 failure investigation. Reviewed the application, ML pipeline, upload path, JSON API, static export, visual-capture tooling, tests, deployment files, and GitHub Actions workflow.

## Findings fixed

| Severity | Finding | Fix |
|---|---|---|
| High | Public `/api/benchmark` accepted `fresh: true` with no abuse guard, allowing repeated expensive retraining. | Added a 30-second process-local cooldown with HTTP 429 + Retry-After; configurable via `FRESH_BENCHMARK_COOLDOWN`. |
| Medium | CI visual regeneration could race a newer push and fail its final `git push` with a stale branch rejection. | Added workflow concurrency cancellation so stale runs are canceled before they can publish generated visuals. |
| Medium | CI requested `contents: write` for every job, although only the visual publishing job needs it. | Defaulted workflow permissions to `contents: read`; granted write only to `visuals`. |
| Medium | Visual capture used an out-of-range prediction fixture (`MockInterviewScore=8`, `ExtraCurricular=2`), so the generated prediction screenshot could show validation errors instead of a real result. | Replaced with valid values and made the visual test fail if a prediction verdict is not rendered. |
| Low | Upload preview rendered missing numeric cells as raw Python `nan`. | Missing preview cells now render as an explicit `—` marker; regression test added. |
| Low | Training-time copy still said ~40s after the current 3-fold/12k recipe had reduced cold training to about 10s in the audited environment. | Updated README, model card, training page, and client-side benchmark copy. |

## Verification

- CI #38 previously completed successfully after the contributor-attribution fix.
- The follow-up changes are now queued for the next CI run.
- Existing repository tests cover API validation, model selection, degenerate datasets, upload security, EDA, artifacts, routes, and prediction behavior.
- A new regression test covers the fresh-benchmark 429 protection.
- A new upload-preview regression test rejects raw `>nan<` output.
- The visual capture path now validates that its prediction fixture actually produces a prediction result.

## Residual bounded limitations

1. Upload files belonging to abandoned sessions are still cleaned primarily at process startup rather than by a persistent storage janitor.
2. Fresh-benchmark throttling is process-local because the deployment intentionally uses a single Gunicorn worker; a distributed deployment should use shared rate-limit storage.
3. The current CI run must finish before this follow-up can be called fully release-verified.

## Verdict

No unresolved P0/P1 application defect was found in this follow-up. The newly identified production/CI issues above have been patched and regression coverage added where practical.
