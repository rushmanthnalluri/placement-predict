# Placement Predict — Final Repository Audit 2026-10-07

## Scope

Final hardening audit of the full repository after the forensic audit and CI failure investigation. Reviewed the Flask application, upload/data contract, EDA pipeline, model training and artifact loading, prediction/API paths, templates and visualization behavior, tests, Docker/Render deployment configuration, GitHub Actions, and generated visual outputs.

## Findings fixed in the final pass

| Severity | Finding | Fix |
|---|---|---|
| High | Uploaded datasets had weaker validation outside the upload happy path, allowing invalid numeric/finite values to reach EDA or ML callers. | Added one shared `validate_dataset()` contract for required columns, numeric types, finite values, non-empty data, complete-feature checks, and binary `PlacementStatus`; used it at upload, EDA, and model-training boundaries. |
| High | An active upload whose EDA analysis failed could silently fall back to the bundled default dataset, making the UI appear healthy while showing the wrong data. | Removed the silent fallback; the active filename is preserved and analysis failure is surfaced explicitly. |
| Medium | Malformed `/api/predict` JSON was parsed after model acquisition, so a bad request could trigger unnecessary cold training. | Parse and validate the JSON body before loading/training any model. |
| Medium | API prediction/benchmark estimator failures could escape as non-JSON 500 responses. | Added guarded prediction/benchmark execution with stable JSON 503 contracts and generic client-safe messages; internal details remain in server logs. |
| Medium | Per-model artifacts were validated by version, dataset hash, and environment but not by their expected model key/object shape, so a swapped artifact could be trusted. | Bind each artifact to its expected registry key and validate classifier/scaler/imputation/regressor structure before use. |
| Medium | Fresh benchmark throttling used only a cooldown timestamp, so concurrent expensive fresh runs could overlap. | Added process-local single-flight protection with HTTP 429 + `Retry-After`, while retaining the configurable cooldown. |
| Medium | XLSX intake was bounded by expanded ZIP bytes but not archive member count. | Added a 10,000-member XLSX ZIP limit before pandas/openpyxl processing. |
| Low | Dataset cache freshness depended on coarse file modification timestamps. | Cache keys now use nanosecond mtime plus size. |
| Low | Negative correlations were clamped to zero in the EDA heatmap, producing an incorrect visual encoding. | Added a diverging negative/neutral/positive color scale and updated the legend/contrast logic. |
| Low | Stage pages described analysis failures as schema mismatches. | Added an explicit analysis-error state across the affected stage templates and API responses. |
| Low | CI proved image buildability but did not exercise the container at runtime. | Added compileall, `pip check`, and a real Docker `/api/health` smoke test. |

## Residual bounded limitations

1. Abandoned-session uploads are still cleaned primarily at process startup rather than by a persistent storage janitor.
2. Fresh-benchmark throttling remains process-local; a future multi-worker/distributed deployment should use shared rate-limit state.
3. Model artifacts are intentionally environment-bound and will be retrained when the Python/numpy/pandas/scikit-learn runtime changes.
